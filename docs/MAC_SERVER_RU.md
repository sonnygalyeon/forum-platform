# Mac как тестовый сервер Night Iris

Этот режим запускает отдельную публичную тестовую копию форума на Mac через
Docker Desktop. Для первого запуска не нужны домен, белый IP или настройка
роутера. Скрипт получает два временных HTTPS-адреса Cloudflare Quick Tunnel:
для сайта и для загрузок. Собеседнику достаточно отправить адрес **Site**.
База, пользователи и файлы находятся на Mac; HTTP-трафик проходит через Cloudflare.

## Запуск

Откройте Docker Desktop и дождитесь запуска движка. В терминале перейдите
в существующую папку `forum-platform` и выполните:

```bash
git status --short
git fetch origin
git switch ver1.2-discovery
git pull --ff-only origin ver1.2-discovery
sh scripts/mac_server.sh start
```

Если `git status` показывает ваши изменения, сначала сохраните их:
порядок действий описан в [инструкции обновления](LOCAL_DEVELOPMENT_RU.md).
Не используйте `reset --hard` для перехода на эту ветку.

Первая сборка скачивает образы и зависимости, поэтому может занять несколько
минут. Повторные запуски используют кеш. Образы поддерживают Apple Silicon
(в том числе M3) и Intel; запуск через эмуляцию x86 не нужен.

В конце будет напечатано:

```text
Night Iris server is ready.
Site:  https://<выданный-адрес>.trycloudflare.com
Files: https://<другой-адрес>.trycloudflare.com
```

Откройте **Site** на Mac, затем на телефоне с отключённым Wi-Fi, через мобильную
сеть. Зарегистрируйте тестового пользователя, войдите, проверьте публикацию,
личное сообщение и загрузку изображения. Адрес **Files** сайт использует
автоматически; открытие его корня выдаёт 404 — это нормально.

Скрипт проверяет локальную готовность и доступность сайта по публичному HTTPS
с самого Mac. Проверка на телефоне нужна отдельно: доступность туннельного
провайдера зависит от сети посетителя.

## Администратор и управление

Создать администратора (пароль вводится локально, при вводе символы не видны):

```bash
sh scripts/mac_server.sh admin
```

Затем войдите этим аккаунтом через обычную страницу входа форума. Админ-панель
находится по адресу `/admin` на домене **Site**.

```bash
sh scripts/mac_server.sh status
sh scripts/mac_server.sh logs
sh scripts/mac_server.sh stop
```

`stop` отключает публичный доступ и останавливает контейнеры. Пользователи,
публикации, загрузки и секреты сохраняются. После изменения кода снова
выполните `sh scripts/mac_server.sh start`.

Во время демонстрации держите Mac подключённым к питанию, оставьте крышку
открытой и запустите в отдельном терминале:

```bash
caffeinate -is
```

Завершение этой команды — `Ctrl+C`. Она не заменяет запущенный Docker Desktop
и не обеспечивает работу ноутбука с закрытой крышкой. После перезапуска Mac
запустите Docker Desktop и `sh scripts/mac_server.sh start` снова.

## Данные и адреса

- Это отдельный Docker-проект `night-iris-mac`. При первом запуске база пустая.
  Данные прежнего локального режима `dev_up.sh` автоматически не переносятся.
- Секреты генерируются в `.env.mac` с правами `600`; файл не попадает в Git
  или Docker-образ. Сохраните его: удаление файла не сбрасывает пароль уже
  созданной базы, а новые случайные пароли не подойдут к существующим томам.
- PostgreSQL, Redis и загрузки сохраняются в Docker-томах этого проекта.
  Не удаляйте тома в Docker Desktop и не запускайте `down -v`, если данные нужны.
- Каждый `start` создаёт новые временные адреса. Перешлите посетителям новый
  **Site**; после смены домена им потребуется войти заново. Старые прямые ссылки
  на файлы перестанут работать; при открытии сайта создаются новые ссылки.
- Перезапускайте туннели через скрипт: он обновляет допустимые домены, CORS,
  WebSocket и подписанные ссылки согласованно. Автоперезапуск туннелей отключён.
- Это временная демонстрация с тестовыми данными. Режим использует локальное
  хранилище MinIO из dev-окружения; постоянный production использует внешний
  поддерживаемый S3-провайдер из `compose.prod.yaml`. Антивирус в демо не включён.
- Лимит файла в демо — 100 MiB, размер части — 16 MiB. Файлы доступны только
  по подписанным ссылкам; консоль и служебное API хранилища наружу не выходят.
- Сайт работает, пока включены Mac, интернет, Docker и оба туннеля.
  Quick Tunnels не гарантируют постоянный адрес или бесперебойность; текущий
  лимит — 200 одновременных запросов, SSE не поддерживается. Форум использует
  WebSocket, который туннель поддерживает.

## Если запуск не удался

```bash
sh scripts/mac_server.sh status
sh scripts/mac_server.sh logs tunnel-app tunnel-media
sh scripts/mac_server.sh logs api frontend gateway
```

При ошибке после начала переключения скрипт отключает публичные туннели и
шлюз, сохраняя данные. При ошибке сборки уже работающий сервер продолжает
работать. Исправьте причину и повторите `start`.

`Connect timeout` при скачивании Python-пакета относится к сети внутри Docker.
Проверяйте загрузку внутри контейнера: успешный `curl` из macOS проверяет только
соединение самой системы. После восстановления сети повторите запуск —
готовые слои сборки останутся в кеше.

Cloudflare сообщает об ограничениях доступа у части российских провайдеров.
Поэтому открытие сайта на Mac не гарантирует доступ через мобильную сеть
другого пользователя. Если Quick Tunnel не выдаёт адрес или сайт недоступен,
сохраните последние строки логов без содержимого `.env.mac`. Для диагностики
не отключайте брандмауэр и не открывайте порты базы или MinIO на роутере.

## Другой туннель или постоянные домены

Шлюз поддерживает любой HTTPS-туннель, сохраняющий исходный HTTP-заголовок
`Host` и поддерживающий WebSocket. Нужны **два разных домена**:

```bash
sh scripts/mac_server.sh start --domains forum.example.com files.example.com
```

Настройте выбранный туннель: `forum.example.com` → `http://127.0.0.1:9080`,
`files.example.com` → `http://127.0.0.1:9081`. Он должен обслуживать HTTPS
снаружи. В режиме `--domains` скрипт не запускает Cloudflare и не проверяет
доступность внешнего провайдера. DNS-записи сами по себе не создают туннель.
Оба локальных порта привязаны только к `127.0.0.1`; не меняйте это на `0.0.0.0`.

## Проверки реализации

CI собирает production-образы, поднимает отдельный стек и проверяет реальные
маршруты Caddy → Next.js → Django и Caddy → MinIO: регистрацию и вход,
Secure/HttpOnly cookies, WebSocket и отклонение чужого Origin, CORS,
подписанную multipart-загрузку и скачивание, запрет анонимного доступа к файлам
и закрытость служебных маршрутов. В CI публичный туннель не создаётся.

Эту проверку можно повторить локально; она создаёт и удаляет собственного
временного пользователя и маленький файл:

```bash
sh scripts/mac_server.sh compose exec -T api python scripts/mac_smoke.py
```
